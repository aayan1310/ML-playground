# AGENTS.md - ML Playground

## Project goal

An educational web game that teaches kids (students) how machine learning works.
Students never upload images. They pick from a fixed set of bundled cat and dog
images, sort them into a "cat" box and a "dog" box (the student does the
labeling, so they can make mistakes), press **Train**, and then test the model on
images it has never seen, seeing the prediction and a confidence score.

The game is **static and browser-only**: images and precomputed embeddings are
shipped as files (no server, no running ML, no torch in the browser). A future
TypeScript engine trains a small linear classifier in the browser on the
student's labels. **The frontend/ (UI) and the TypeScript engine are not built
yet.**

To keep the classifier tiny and fast, each image is precomputed ONCE offline
into a 512-dim vector: a pretrained ResNet18 turns the image into a list of
numbers. The browser classifier trains on those stored numbers.

## The pipeline (run in order)

1. `prep/prepare_dataset.py` — needs torch. Downloads Oxford-IIIT Pet
   (`binary-category`), picks a fixed set (seed 42) of 30 cats + 30 dogs,
   resizes longer side <= 512px, writes `data/images/` (`cat_001…dog_030`) and
   `data/manifest.json` (22 train / 8 test per class). Cross-checks the
   dataset's binary label against the filename-capitalization rule (cat breed
   names uppercase, dogs lowercase) and stops on disagreement.
2. `prep/compute_embeddings.py` — needs torch. ResNet18 (ImageNet weights,
   `model.fc = Identity`), standard ImageNet preprocessing, `model.eval()` +
   `torch.no_grad()`, L2-normalized, writes `data/embeddings.npy` in manifest
   order.
3. `prep/export_browser_data.py` — numpy only. Shuffles the ids with a fixed
   seed so filenames never reveal the class: `img_001…img_060` (seed 42), and
   shuffles train/test with seed+1 so cats and dogs interleave. Writes
   `public/ml-playground/` and the prep-only `data/id_mapping.json`.
4. `prep/evaluate_offline.py` — numpy + scikit-learn. Measures the reference
   `LogisticRegression` (C=10, lbfgs, l2, max_iter=1000): perfect labels,
   train-size sweep (n=3/5/10/15/22, mean+min), labeling-mistake sweep
   (0%-30% incl. 25%), and confidence on correct vs wrong predictions.
   `--json-out ../docs/evaluation-results.json` for docs.

Steps 3-4 are cheap and re-runnable without torch; steps 1-2 need torch and run
once. The browser app is only touched by step 3's output.

## The contract (IMPORTANT)

- The browser's data is `public/ml-playground/`; the exact schemas and the
  future TS engine's API (`parseData`, `attachLabels`, `labelCheck`, `train`,
  `predict`, `evaluate`, error codes `dataset_invalid` / `labels_invalid` /
  `labels_not_loaded` + rule codes) are specified in **`docs/data-contract.md`**.
  Read it before writing any browser/engine code or touching the public files.
- Rule: at least 3 images per box; no id in both boxes; unknown ids and ids
  outside the train pool are errors. Test accuracy is scored on the 16 held-out
  test images using TRUE labels.
- `labels.json` is fetched by the UI **only when the student presses Train**.
  `manifest.json` and `id_mapping.json` are prep-internal and must never be
  shipped or served.
- Reference algorithm for the engine: sklearn `LogisticRegression(C=10,
  max_iter=1000)` (solver lbfgs, penalty l2). The TS engine approximates it;
  see `docs/evaluation.md` for the accuracy targets.

## What still needs building (future tasks)

## Constraints

- The browser app must NOT need torch or any server.
- Do not add a database, login, uploads, a server, or extra packages/deps
  without asking.
- Keep ids opaque everywhere the browser can see them; keep `labels.json` out of
  `dataset.json` (no label leak before Train).

## Commands (PowerShell, from the repo root)

One-time prep (needs torch):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r prep\requirements-prep.txt
python prep\prepare_dataset.py
python prep\compute_embeddings.py
```

Regenerate browser data + evaluation (numpy + scikit-learn only; the checked-in
`.venv` already has these):

```powershell
.\.venv\Scripts\python.exe prep\export_browser_data.py
.\.venv\Scripts\python.exe prep\evaluate_offline.py --json-out docs\evaluation-results.json
```

Note: the checked-in `.venv` does NOT contain torch; re-running
`prepare_dataset.py`/`compute_embeddings.py` requires installing
`prep/requirements-prep.txt` (or a separate torch venv).
