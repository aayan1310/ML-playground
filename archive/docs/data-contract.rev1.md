# Data contract — ML Playground

Contract between the prepared data (this repo) and the browser app that will be
built later. The browser app is a static site: it loads the files below and
trains a small classifier **in the browser with TypeScript**. There is no server
and no torch in the browser path.

Everything in `public/ml-playground/` is generated by
`prep/export_browser_data.py` (run once, after the prepare + embeddings scripts).
Do not hand-edit these files; if you need to change the data, edit
`prep/data/` and re-run the export.

---

## Part 1 — The data files

All numbers are stored losslessly as JSON. Embeddings are rounded to 6 decimal
places to keep the file small (the vector differences are far below what the
classifier can use, so behavior is unchanged).

### `public/ml-playground/dataset.json`

```json
{
  "train": [ { "id": "img_017", "url": "images/img_017.jpg" }, ... ],
  "test":  [ { "id": "img_033", "url": "images/img_033.jpg" }, ... ]
}
```

- Exactly 44 `train` + 16 `test` entries (22 cats + 22 dogs train, 8 + 8 test
  by TRUE label).
- **No labels and no class info anywhere in this file.** Ids and urls are
  opaque (`img_001` … `img_060`); pool order is shuffled (seed 42 + 1) so cats
  and dogs are interleaved and a position never reveals the class.
- `url` is relative to `public/ml-playground/` and points at `images/<id>.jpg`.
- `train`/`test` never overlap and their union is exactly the 60 images.

### `public/ml-playground/embeddings.json`

```json
{
  "dim": 512,
  "ids":  [ "img_017", "img_033", ... ],   // all 60 ids, length == 60
  "vectors": [ [0.034, -0.021, ...], ... ]  // vectors[i] is the embedding of ids[i]
}
```

- One 512-dim vector per image. Each vector is **L2-normalized** (unit length)
  and rounded to 6 decimal places.
- The embedding comes from a pretrained ResNet18 (ImageNet weights) run on a
  224x224 center crop of the image, so roughly: visual-idea-of-the-image →
  512 numbers. Two images of the same class have similar vectors.
- `vectors[i].length == dim` for every `i`, and `ids` matches dataset ids
  exactly (same 60, as a set).

### `public/ml-playground/labels.json`

```json
{ "img_017": "cat", "img_033": "dog", ... }
```

- A flat object with all **60** ids, each mapping to `"cat"` or `"dog"` (the
  TRUE label).
- This is the file that lets the app show "correct / incorrect" on the test
  images. It is intentionally kept out of `dataset.json` so nothing leaks
  before the student presses **Train**.

### `public/ml-playground/images/`

`img_001.jpg` … `img_060.jpg`, the JPEG images referenced by `dataset.json`.
Same set of 60 images as the embeddings, but with **neutral filenames**.

### Not in `public/ml-playground/` (never ship)

- `manifest.json` — prep-internal source of truth (`prep/data/manifest.json`).
- `id_mapping.json` — the prep-only map from `img_XXX` back to the original
  `cat_001…dog_030` names (`prep/data/id_mapping.json`). If you can map an id
  back to its original name without this file, the data pipeline has a bug.

### Math the app can trust

- Every id appears exactly once, and `dataset.train ∪ dataset.test` == `labels`
  keys == `embeddings.ids`.
- Vectors are unit length, so dot products are cosine similarities in `[-1, 1]`.
- The 16 test ids are the same across runs (fixed seed); classes are balanced.

## Part 2: ENGINE (frontend/src/features/ml-playground/engine)

Pure TypeScript: no React, no fetch, no randomness, no I/O, no input mutation.

```ts
type Label = "cat" | "dog"

type Box = 0 | 1
// 0 is the Cat box, 1 is the Dog box. cat maps to 0, dog to 1.

interface PlaygroundData {
  trainIds: string[]
  testIds: string[]
  urls: ReadonlyMap<string, string>
  vectors: ReadonlyMap<string, readonly number[]>
  dim: number
  labels: ReadonlyMap<string, Label> | null
}

interface Choice {
  id: string          // one picture the student sorted
  box: Box
}

interface Model {
  weights: number[]             // plain readable object; the UI only needs countPerBox
  bias: number
  dim: number
  countPerBox: [number, number]
}

interface Prediction {
  imageId: string
  box: Box
  confidence: number
  probabilities: [number, number]  // probabilities[0] = P(cat), [1] = P(dog)
  trueBox: Box
  correct: boolean
}

interface Evaluation {
  accuracy: number
  correct: number
  total: number
  perItem: Prediction[]
}

interface LabelCheckResult {
  correct: number
  total: number
  wrongIds: string[]
}
```

Errors: every function throws `PlaygroundError` with a stable `code`, a plain
English `message` and an optional `detail` object. Codes: `dataset_invalid`,
`embeddings_invalid`, `ids_mismatch`, `labels_invalid`, `labels_not_loaded`,
`unknown_id`, `not_in_train_pool`, `not_in_test_pool`, `duplicate_id`,
`invalid_box`, `too_few_in_box`, `model_mismatch`, `numeric_failure`.

### `parseData(dataset: unknown, embeddings: unknown): PlaygroundData`

- Validates both files; `labels` is null. `trainIds` and `testIds` keep file order.
- `dataset_invalid`: train or test missing, empty or not an array; an item
  without a non-empty string id and a string url; duplicate ids (also across
  train and test).
- `embeddings_invalid`: dim not a positive integer; ids and vectors lengths
  differ; a vector whose length is not dim; a non-finite number.
- `ids_mismatch`: the two files do not contain exactly the same set of ids.

### `attachLabels(data: PlaygroundData, labels: unknown): PlaygroundData`

- Returns a NEW object with labels set; never mutates. `labels_invalid` if
  labels is not an object, an id is missing or extra, a value is not "cat" or
  "dog", or either split has fewer than 3 pictures of each label.

### `train(data, choices: Choice[]): Model`

- Uses the STUDENT'S boxes as labels, never the true labels; needs no labels.
- Logistic regression, the Dog box is the positive class, zero initial weights,
  deterministic, no randomness. Choices are sorted by id internally, so their
  order never changes the result. Same input gives the same Model.
- Check order and errors: `invalid_box` (box not 0 or 1), `unknown_id`,
  `not_in_train_pool` (a test picture), `duplicate_id`, then `too_few_in_box`
  (a box has fewer than 3; detail `{ box, have, need }`), then `numeric_failure`
  if any value is not finite.
- Target: the sklearn `LogisticRegression(C=10)` reference — the accuracy and
  confidence numbers it must match are in `docs/evaluation.md`, pinned by the
  golden fixtures in `__fixtures__/golden.json`.

### `predict(data, model, imageId: string): Prediction`

- Needs labels. Check order: `labels_not_loaded`, `unknown_id`,
  `not_in_test_pool`, `model_mismatch` (model.dim differs from data.dim),
  `numeric_failure`.
- `box` is the more likely box (an exact tie gives box 0); probabilities sum to
  1 within 1e-9; `confidence` is the larger probability (0.5 to 1); `trueBox`
  comes from the labels; `correct` is box equals trueBox.

### `evaluate(data, model): Evaluation`

- Needs labels. Predicts every test picture in `testIds` order. `accuracy` is
  correct divided by total, from 0 to 1. Check order: `labels_not_loaded`,
  `model_mismatch`, `numeric_failure`.

### `labelCheck(data, choices: Choice[]): LabelCheckResult`

- Needs labels. Compares each choice's box to the TRUE box of that picture. It
  does not use or evaluate a model. `correct` is the number that match; `total`
  is `choices.length`; `wrongIds` is sorted. Zero choices gives
  `{ correct: 0, total: 0, wrongIds: [] }`. The minimum of 3 per box does NOT
  apply.
- Check order: `labels_not_loaded`, `invalid_box`, `unknown_id`,
  `not_in_train_pool`, `duplicate_id`.

## MAP — original ids turn into opaque ids

This is prep-internal (see `prep/data/id_mapping.json`), included so a
troubleshooter can confirm the pipeline:

```
img_001 … img_060  =  fixed random permutation (seed 42) of manifest order
manifest rows      =  cat_001…030 then dog_001…030 (alphabetical per class)
```
